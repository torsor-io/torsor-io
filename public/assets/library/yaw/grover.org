~yaw~ is a ~Python~-based language for doing algebraic quantum
programming. This tutorial explains how to perform
Grover search, introducing qudit systems and their applications en
route, and gives a (mildly novel) pedagogical overview of the
algorithm. We assume familiarity with prior tutorials ([[https://torsor.io/assets/library/yaw/yaw011.html][1]] and [[https://torsor.io/assets/library/yaw/teleport.html][2]]).

* Setup
-----
In this tutorial, we'll be using /qudits/, the higher-dimensional
cousin of qubits. These are natural for unstructured search, with a
database of $d$ objects corresponding to a qudit with $d$ orthogonal
states.
We'll be using the algebraic approach, however, which is less familiar
and requires a little preparation.
** The algebra of qudits
With qubits, we typically set up an algebra generated by the Pauli $X$
and $Z$.
We can define these abstractly by the fact that they are unitary, and
obey
\[
X^2 = Z^2 = I, \quad ZX = -XZ. \tag{1}\label{pauli-1}
\]
Equivalently, we can think of how they act on the computational basis
$|0\rangle, |1\rangle$:
\[
Z|b\rangle = (-1)^b |0\rangle, \quad X |b\rangle = |b+1 \rangle, \tag{2}\label{pauli-2}
\]
where $b + 1$ is interpreted modulo $2$.
There is a very similar story for qudits, which is variously called
the /generalized Clifford algebra/, the /Sylvester matrices/, or the
/Weyl-Heisenberg matrices/. We'll go with "generalized Clifford
algebra" and denote it $\mathcal{A}_d$. We still have operators $X$ and $Z$,
called the /shift/ and /clock/ operator respectively, and akin to
(\ref{pauli-1}), they are unitary and obey
\[
X^d = Z^d = I, \quad ZX = \omega_d XZ, \tag{3} \label{clifford-1}
\]
where $\omega_d = e^{2\pi i/d}$. Equivalently, they act on a
computational basis of states $|0\rangle, |1\rangle,
\ldots, |d-1\rangle$ via
\[
Z |i\rangle = \omega_d^i |i\rangle, \quad X |i\rangle = |i+1\rangle. \tag{4} \label{clifford-2}
\]
It's easy to check that this reduces to the Pauli algebra
(\ref{pauli-1}) and (\ref{pauli-2}) for $d=2$.
This is not the only generalization of the Pauli algebra, but it is a
convenient one, since it lets us import the maximum amount of
intuition from the qubit case.
Note that although $Z$ is no longer Hermitian, we can still measure in
the computational basis! All we need is the PVM associated to $Z$,
which is $\Pi_i = |i\rangle\langle i|$ as usual.
** Using qudits in ~yaw~
In ~yaw~ using qudits is easy. First, we have a syntactic
sugar:
#+BEGIN_EXAMPLE python
yaw> $alg = qudit(d)
#+END_EXAMPLE
This gives immediate access to clock $Z$ and shift $X$ operators
associated with the generalized Clifford algebra $\mathcal{A}_d$.
Under the hood, this implements the defining relations
(\ref{clifford-1}) of the algebra:
#+BEGIN_EXAMPLE python
yaw> $alg = < X, Z|unit, pow(d), braid(exp(-2*pi*I/d)) >
#+END_EXAMPLE
where ~braid(ω)~ means that ~X*Z = ω*Z*X~.
* Grover's algorithm*
This presents Grover's algorithm from a slightly unconventional
perspective, focused on justifying /why/ it works from the more
advanced perspective of simulation and speed limits. If you already feel comfortable with
the material, feel free to skip to the implementation in the next
section!
** Introduction
Say we have an unstructured collection of $d$ items, and a single
"marked" item, say $m$. We encode the database into the computational basis
states $|i\rangle$ of a qudit, and an /oracle/ which encodes whether the
item is marked into the phase:
\[
U |i\rangle = (-1)^{\delta_{im}} |i\rangle.
\]
This is the usual picture. In terms of operators, we have the
generalized Clifford algebra $\mathcal{A}_d$ and an oracle
\[
U = I - 2 \Pi_m \tag{5} \label{grover5}
\]
where $\Pi_m = |m\rangle\langle m|$ projects onto the marked element.
There is no way to "extract" $m$ from the oracle; like a perfect
combination lock, the best classical method is brute force, testing
each $|i\rangle$ until we get the right phase. This will take
$\mathcal{O}(d)$ steps, since we have to scan around half the entries, on average,
before we hit the right one. Can we do better with a quantum computer?

We can! Quantum mechanics allows us to try "all solutions at once". More
precisely, we can start with the initial guess
\[
\frac{1}{\sqrt{d}}(|0\rangle + \cdots + |d-1\rangle) = |+\rangle \tag{5}
\]
which is the $+1$-eigenstate of the shift operator $X$.@@html:<label for="mn-demo" class="margin-toggle">&#8853;</label>
<input type="checkbox" id="mn-demo" class="margin-toggle"/>
<span class="marginnote">
A sum with equal weights is invariant under shifts.
</span>@@
But applying the oracle by itself does not help.
Instead, we need to use the oracle to concentrate this initially
uniform guess with increasing probability on the correct answer $|m\rangle$.
** How it works
In the same way that we form the oracle from the projector $\Pi_m$, we
can form something called the /diffusion operator/ $D$ from $\Pi_+
= |+\rangle\langle +|$:
\[
D = I - 2 \Pi_+. \tag{6}\label{grover6}
\]
This "flips" the $|+\rangle$ state in the $X$ eigenbasis and leaves
the orthogonal eigenstates alone.
The algorithm combines $U$ and $D$ into the /Grover operator/ $G$:
\[
G = DU. \tag{7} \label{grover7}
\]
It turns out (for reasons we explain in the next section) that
applying the Grover operator gradually "rotates" $|+\rangle$ in the
direction of $|m\rangle$. It takes an equal step towards $|m\rangle$
with each iteration of $G$, so it can /overshoot/; the optimal number
of repetitions is
\[
r = \left\lceil \frac{\pi\sqrt{d}}{4}\right\rceil. \tag{8} \label{grover8}
\]
The number of Grover steps scales as
$\mathcal{O}(\sqrt{d})$, so we have the famous quadratic speedup.
To be clear, the algorithm is to apply $G$ a total of $r$ times
to the uniform guess $|+\rangle$, measure in the computational basis,
and guess the measurement outcome is the marked item.
But this is all smoke and mirrors; why on earth should this work?
** Why it works: operators
The usual proof that Grover works is circuitous and involves a lot of
algebra. Here is a cute shortcut: first, note that the exponential of
a projector $\Pi^2 = \Pi$ is
\[
e^{\alpha \Pi} = I + \sum_{k\geq 1} \frac{1}{k!} (\alpha \Pi)^k = I +
\Pi\sum_{k\geq 1} \frac{\alpha^k}{k!} = I + (e^\alpha - 1)\Pi
\]
since $\Pi^k = \Pi$ for all $k \geq 1$.
If we choose
\[
\alpha = \log 3 + \pi i \quad \Longrightarrow \quad e^{\alpha \Pi} = I  -2\Pi.
\]
Next, the /Trotter-Suzuki identity/
states that, for potentially non-commuting $A$ and $B$,
\[
e^{A + B} = \lim_{r\to\infty} \left(e^{A/r}e^{B/r}\right)^r,
\]
which can be proved by Taylor expanding.
If you fix $r$ large, then we expect
\[
e^{r(A + B)} \approx \left(e^{A}e^{B}\right)^r.
\]
Thus, for the special choice of $\alpha$ above, we have
\[
G^r \approx \exp\left[r \alpha \left(\Pi_+ +
\Pi_m\right)\right]. \tag{9} \label{ham}
\]
The question is what this operator does. We claim it turns $|+\rangle$
into $|m\rangle$, and vice-versa; you can check this in the
exercises. So we now have a sense of why this particular combination
of operators works. @@html:<label for="mn-demo" class="margin-toggle">&#8853;</label>
<input type="checkbox" id="mn-demo" class="margin-toggle"/>
<span class="marginnote">
We will ignore the problem of log 3, which represents a sort of <i>imaginary time</i> evolution.
</span>@@ 
** Why it works: steps
What we don't yet understand is where the optimal number of steps $r =
\mathcal{O}(\sqrt{d})$ comes from.
For this purpose, it is helpful to think of the exponent in
(\ref{ham}) as a /Hamiltonian/:
\[
H_m = \Pi_+ + \Pi_m.
\]
Iterating the Grover operator is equivalent to evolving with this Hamiltonian.
The exercises show that evolution with the operator from the previous
section stays within a two-level subspace spanned by $|+\rangle$ and
$|m\rangle$; for this type of evolution, the /minimum/ time $t^*$
needed to transition between two states $|i\rangle$ and $|f\rangle$ is
governed by the /Rabi uncertainty principle/
\[
t^* \geq \frac{\pi}{2|\langle i|H|f\rangle|},
\tag{10}
\]
(where we use units in which $\hbar = 1$) as the exercises establish.
For initial state $|i\rangle = |+\rangle$ and final state $|f\rangle
=|m\rangle$, this transition element is
\[|
\langle i|H|f\rangle| = \langle + | \left( |+\rangle\langle
+| + |m\rangle\langle m|\right) |m\rangle = \frac{2}{\sqrt{d}},
\]
since $\langle +|m\rangle = 1/\sqrt{d}$. Thus, we learn that the
minimum time needed to transition between elements is
\[
t^* \geq \frac{\pi \sqrt{d}}{4},
\]
which is exactly the number of steps we claimed were optimal! The
$\alpha$ term contributes only an overall constant, which can be
viewed as normalizing the length of a step, and in particular, doesn't
change the $\mathcal{O}(\sqrt{d})$ scaling which is the main
takeaway.
Now, on to the implementation!
** Mutiple items
The story for multiple marked items is almost exactly the
same. For a set $M = \{m_1, \ldots, m_{|M|}\}$ of marked items, we
replace the state $|m\rangle$ in above discussion with the uniform superposition
\[|
M\rangle = \frac{1}{\sqrt{|M|}}(|m_1\rangle + \cdots + |m_{|M|}\rangle).
\]
The oracle $U = I - 2\Pi_M$, $G = DU$, and the effective Hamiltonian
which evolves the initial guess is
\[
H_M = |+\rangle\langle +| + |M\rangle\langle M|.
\]
Precisely the same analysis using the Rabi uncertainty gives
\[
t^* = \frac{\pi}{2\langle +|H_M | M\rangle} = \frac{\pi}{4\langle
+|M\rangle} = \frac{\pi}{4}\sqrt{\frac{d}{|M|}}.
\]
More marked items requires fewer steps, which makes sense!
* Grover in ~yaw~
After all the work needed to understand the algorithm, the code is
fairly straightforward.
** Line by line
Here, we work with compiled ~yaw~. We start by setting up a function
which will measure and thus stochastically guess the marked item. As
discussed above, we can invoke the ~qudit(d)~ convenience function:
#+BEGIN_EXAMPLE python
def grover(mark, d):
    $alg = qudit(d)
#+END_EXAMPLE
Next, we define a helper function to turn projectors $\Pi$
into operators $R(\Pi) = I - 2\Pi$ that "flip" the space projected onto:@@html:<label for="mn-demo"
class="margin-toggle">&#8853;</label>
<input type="checkbox" id="mn-demo" class="margin-toggle"/>
<span class="marginnote">
Note that we define this inside the function so that <code>I</code>
refers to the identity of the <code>$alg</code> just defined.
</span>@@
#+BEGIN_EXAMPLE python
... def reflect(P): return I - 2*P
#+END_EXAMPLE
We will use this to define the oracle (\ref{grover5}) and diffusion
operator (\ref{grover6}).
Next, we define the Grover operator (\ref{grover7}):
#+BEGIN_EXAMPLE python
... G = reflect(proj(Z, mark)) * (-reflect(proj(X, 0)))
#+END_EXAMPLE
Note that $|m\rangle$ is eigenstate $m$ of $Z$ (according to our
ordering), hence ~proj(Z, mark)~, and similarly the $|+\rangle$ state
is eigenstate $0$ of $X$, hence ~proj(X, 0)~. We then choose the
number of iterations according to (\ref{grover8}):
#+BEGIN_EXAMPLE python
... r = int((pi/4)*sqrt(d))
#+END_EXAMPLE
We use the ~int~ function to round to the nearest integer.
Finally, we apply the Grover operator $r$ times to the state
$|+\rangle$ (represented by ~proj(X, 0)~) using the state conjugation
operator ~<<~ and measure:
#+BEGIN_EXAMPLE python
... _, guess = measure(Z, (G**r) << char(X, 0))()
    return guess
#+END_EXAMPLE
Putting it all together, we have the compact program:
#+BEGIN_EXAMPLE python
def grover(mark, d):
    $alg = qudit(d)
    def reflect(P): return I - 2*P
    G = reflect(proj(Z, mark)) * (-reflect(proj(X, 0)))
    r = int((pi/4)*sqrt(d))
    _, guess = measure(Z, (G**r) << char(X, 0))()
    return guess
#+END_EXAMPLE
Let's run it and get some numbers!
